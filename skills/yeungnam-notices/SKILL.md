# 岭南大学计算机学部公告查询

## 入口与范围

- 学校是韩国 영남대학교 / Yeungnam University，不是香港岭南大学。
- 计算机学部公告栏：https://computer.yu.ac.kr/computer/notice/notice.do
- 专业通知和学部共同通知可能分开发布。从当前官网导航确认相关入口，不猜路径；说明查到了哪个栏目。
- 入口是本次经验保存的起点，不保证永久有效。失效时从学校官方站点寻找院系导航，记录新的已核验入口。
- 这是查询技能；不因加载技能而创建或修改定时任务。课程清单从当前用户材料取得，不沿用历史学期作为默认。

## 查询流程

官方公告 → 正文及附件版本 → 课程编号匹配 → 与旧表对比 → 中文结果及来源。

1. 根据请求打开公告栏或指定公告。查“最新”时访问当前页面；仅核对用户上传材料时说明依据的材料版本，不声称已实时查证官网。
2. 保存公告标题、直达链接、articleNo、发布日期、正文修订说明、附件名称和本次核验日期。详情链接可用 `notice.do?mode=view&articleNo=<实际编号>`，去掉分页参数仍保留编号。
3. 同一 articleNo 可能原地改正文或换附件，不能把“无新编号”等同于“内容未变”。对更新查询比较正文更正段落、附件列表和实际附件内容；有既存基线时比较内容摘要或文件哈希。下载次数、浏览量、置顶或排序变化不算实质修订。
4. 提取与用户问题相关的正文和附件。区分考试时间表、追加考试申请书等用途；不要把申请表当作考试安排。
5. 按下述课程和冲突规则核对，输出完整结果；网页不可访问或附件无法读取时保留已知版本，明确本次未核实的部分，不声称没有变化。

## 匹配课程及读表

- 以课程编号和分班为匹配依据，名称及教师仅作辅助。例如用户 `1180-04` 可与 PDF 编号 `1180` 对应，但 PDF 未给分班时说明该限制；出现分班专属通知时按实际分班核对。
- 同名课程不同编号不能互套更正；同一教师也可能教授多个编号的课程。
- PDF 先提取文字，再目视检查相关页的日期列、时间行、课程格、跨格/合并格及考场。文字提取可能错列，行标签也可能没有同步更正。
- 搜索所有相关页；未匹配到的课程写“未找到考试安排”，不能推断为无考试。缺日期、考场或结束时间时分别标明待确认，不补猜。
- 多个考场按原文保留；没有个人或分班分配证据时不擅自选一个教室。

## 处理相互矛盾的来源

- 比较适用课程、通知发布/修订时间和是否明确更正旧安排，不设“PDF 永远优先”或“截图永远优先”的固定顺序。
- 公告明确更正某课程时，不能继续套用 PDF 未更新的时间行。教师直接通知明确指定适用课程和安排时，记录该证据与此前来源的关系。
- 用户上传日期不等于通知发布日期；截图缺时间、课程标题或编号时不要编造。结合当前课程上下文判断，关键归属或先后无法确认时标记冲突并询问所缺信息。
- 有冲突的更新说明旧值、新值、来源和采用理由；未能解决的冲突并列展示，不静默覆盖。
- 遇到同名不同编号或正文与附件冲突时，按需阅读 [历史考试案例](references/exam-case.md)。其中时间仅用于理解核对方法，不是当前考试安排。

## 输出

中文答复，时间使用 Asia/Seoul 并明确年份。考试查询用 Markdown 表格：日期（星期）、考试时间、课程、课程编号/分班、考场。更新时突出变化并保留其他已确认行；可加简短旧值→新值对照。普通公告查询列标题、发布日期、摘要和原文链接。

附实际使用的公告/附件链接或本地材料引用、材料版本及核验日期；分别说明实时核验和沿用的历史信息。不把系统当前日期当作来源的修订日期。
