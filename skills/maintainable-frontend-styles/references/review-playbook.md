# 前端样式评审与重构手册

## 评审流程

1. 读取组件、样式、入口和 package/config 文件，确认实际技术栈。
2. 标出每条样式的所有者：组件、主题、页面布局、第三方或全局基础层。
3. 先找正确性问题，再找可维护性问题；不要把个人偏好伪装成缺陷。
4. 按影响范围排序，给出可定位的文件和行号。
5. 需要改动时，从最小、视觉不变的边界开始。

## 常见问题

| ❌ 问题 | ✅ 期望 |
| --- | --- |
| `bg-${tone}-500` 动态构造 Tailwind class | props 映射到完整静态 class |
| 同一元素同时有 `flex grid` | 每个状态只保留一个布局意图 |
| 多个组件样式堆入 `page.module.scss` | 样式随组件 colocate |
| 把重复 class 立即抽成 `.btn` | 跨文件重复先抽 React 组件 |
| 任意值反复出现 | 提升为主题或语义 token |
| `.module.scss` 内大量 `@apply` | Tailwind 与 Sass Module 分工 |
| 深层标签选择器依赖 DOM | 为稳定子部件提供局部 class |
| `!important` 修复覆盖 | 降低 specificity 或明确 cascade layer |
| 宽泛 `:global` | 在局部根节点下收窄第三方选择器 |
| 只有 hover，没有 keyboard focus | 同时提供 `focus-visible` |
| 非必要动画忽略用户偏好 | 提供 reduced-motion 退化 |
| 未经批准安装 Tailwind/Sass | 先提交迁移影响并请求授权 |

不要仅凭文件长就判定必须拆分。报告职责混杂、消费者分散、DOM 耦合或修改扩散等具体证据。

## 迁移审批模板

在缺少 Tailwind 或 Sass 时先给出：

```markdown
建议迁移：[Tailwind / Sass]

- 当前状态：[现有方案与限制]
- 新增依赖：[准确包名，不执行安装]
- 配置改动：[入口、构建插件、扫描范围]
- 本次范围：[仅目标组件 / 指定目录]
- 不在范围：[全仓改写、视觉重设计]
- 收益：[与当前任务直接相关的收益]
- 风险与验证：[构建、CSS 顺序、浏览器或产物风险]

请确认是否允许上述依赖和配置变更。
```

仅在上述变更尚未获授权时等待确认；已有明确授权无需重复询问。

## 视觉不变重构

治理巨型 Module 时：

1. 记录现有组件树、class 绑定、状态、媒体查询、关键帧和全局逃逸。
2. 按组件所有权建立目标文件，不同时重新设计视觉。
3. 一次移动一个职责，更新对应 import 与 `styles.*` 引用。
4. 保持 selector specificity、CSS 顺序和断点行为，除非任务明确要求修复。
5. 把共享值提升为 token；只有结构与行为同时重复时才抽组件。
6. 删除仅由本次移动造成的孤儿规则和 import。
7. 按每阶段影响运行相关检查；涉及入口、构建或 CSS 顺序时验证生产构建。关键视觉行为改变时对照实际界面。

拆分前后都要检查 Next.js 的 CSS import 顺序。生产构建可能合并和分块 CSS，开发环境正常不等于生产顺序正确。

## 验证矩阵

按受影响行为选择下表检查，并保留项目强制门禁；不把本表作为每次修改的全量任务。

| 维度 | 可选验证 |
| --- | --- |
| 静态检查 | formatter、Stylelint、ESLint、类型检查 |
| 构建 | Next.js/Vite 生产构建，无 Sass/Tailwind 警告 |
| 交互 | hover、focus-visible、active、disabled、selected |
| 视口 | 基础移动端、主要断点、内容溢出 |
| 主题 | light/dark、语义 token、forced-colors（适用时） |
| 动效 | reduced-motion 下移除或弱化非必要动画 |
| CSS | 无冲突 utility、无意外全局泄漏、顺序稳定 |
| 回归 | 组件测试、截图或人工前后对比 |

优先运行仓库已有命令。不要擅自引入新的测试、lint 或截图依赖；缺少验证设施时报告人工验证范围。

## 输出格式

代码评审按严重性输出可操作问题。每条包含：

- 位置；
- 观察到的行为或风险；
- 为什么它会影响正确性或维护；
- 最小修复方向；
- 仍需确认的视觉或运行证据。

实现或重构完成时，报告：

1. 选择了哪一层样式方案及原因；
2. 哪些组件或 Module 被拆分、组合或保留；
3. 实际运行的验证及结果；
4. 未运行的检查与剩余风险。
