# 核对与补存 AskSia 课堂转译

手动调用。本次只问“多少条没保存”时，完成核对并报告；要求补存或只给出技能名时，核对后直接保存确定缺失的记录。遵守用户指定的课程、日期和目标目录范围。

## 核对云端与本地

1. 通过官方 Chrome 扩展复用已登录的 AskSia 标签页，入口为 https://www.asksia.ai/pro/files 。默认目标为课程资料工作区里的 `大三上/<课程名>/`；从其他目录调用时可定位到 `~/Documents/Code/Class/课程资料/大三上`。用户指定的学期或路径优先。
2. 清除妨碍本次范围的文件搜索条件，读取「我的文件」表格。滚动表格或翻页，合并重叠视图，与页底“共 N 个文件”核对。保留完整标题、日期和分段后缀；同名行用行标识或修改时间区别。全库包含其他文件时，先点齐列表，再计数范围内的课堂记录。加载不全时明确已核对范围。
3. 列出课程目录内已有的 Markdown。先按完整标题匹配，再比对课程、日期、课次及旧文件名中的“实时转译”等后缀。微处理器与微处理器实验分别匹配。遇到同课次但日期错开、两段录音共用一个本地文件、同名空文件或疑似截断时，打开预览，把各段首尾时间和原文与本地正文比对。足以确认覆盖才计入已保存；无法判断的单列待核实。相同日期的独立录音分别计数。
4. 报告范围内的云端记录数、已保存数、确定缺失数、待核实数，按课程列出缺失标题。仅检查时到此结束。

## 保存确定缺失的记录

1. 逐条按完整标题打开文件预览，等候预览标题与所选记录一致、转译段落加载完成。预览可能把整篇压成一个无障碍文本节点，长课还可能截断。优先从页面渲染的段落结构逐条读取讲者、时间戳、原文和译文。已知布局是在同一段落容器内用两个 span 显示讲者和时间，随后用 p 分别显示韩文和中文；先用当前页面确认结构。
2. 核实首尾段、段数和时间顺序。若预览分批渲染，滚动收齐，保留原顺序，用重叠段定位接续处。播放器总时长可作末段的辅助判断，时长本身不能证明内容完整。区分源记录本就缺译与尚未加载，按页面实有文本保存，说明缺译。无法取得完整转译时跳过该条，继续其余记录。
3. 写入 `<学期>/<课程名>/<AskSia完整标题>.md`，保留标题中的日期、课次及分段编号。必要时替换文件名中的路径分隔符并检查重名。参照同课程已有文件，使用 UTF-8，保留原文、原译、时间戳及讲者编号。每段格式如下，段间空一行，无需额外标题。

   ```text
   讲者 1 · 0:03 · 韩文原文
   中文译文

   讲者 2 · 0:18 · 韩文原文
   中文译文
   ```

4. 在内存中组装完整正文，再以不覆盖已有文件的方式落盘。遇到同名文件时重新比较；中断后重新核对，只补剩余记录。逐份回读，与从预览提取的完整正文比对，核对文件数与段落数。最终按课程报告实际新增、仍缺失或待核实的条目，附目标目录链接。零缺失时无需写入。
