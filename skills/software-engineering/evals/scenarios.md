# 行为评测

仅在维护技能时使用，不在日常开发中加载。结构校验只能证明 frontmatter 和文件链接可用，不能证明自动触发、工程判断或浏览器行为正确。

## 场景与判定

| 场景 | 观察结果 |
| --- | --- |
| 页面私有内容散落共享目录，用户要求工程整理 | 按消费者和依赖修正归属，不只改类型或机械保留原目录 |
| 已有弹窗库覆盖当前生命周期 | 核对 API 后复用；若 URL/兄弟组件需协调则保留必要受控状态 |
| 职责集中的小页面 | 可以保留，不预建 feature/store 或巨型页面 Hook |
| 只改按钮间距 | 只做授权修改，不读取整套架构，不新增 SCSS 或依赖；标明实际视觉验证情况 |
| 普通 Node.js TypeScript 接口修改 | 选择后端专项，不加载前端工作流 |
| 异步搜索与实体切换 | 能验证过期响应、状态身份、关闭重开和焦点相关风险 |
| 源码 Review | 只读，确认可达问题与证据；不把个人目录或样式偏好当 bug |
| 初始截图正常但键盘无法使用控件 | UI Review 应实际操作并发现问题，截图不能代替交互 |
| 长文本或窄屏造成遮挡 | 记录视口和复现步骤，区分观察到的现象与已定位根因 |
| Chrome 连接缺失或诊断能力不足 | 继续可做检查，准确报告 UI 或诊断未验证，不换独立浏览器冒充完成 |
| 无缺陷实现 | 不凑问题，不因文件行数或组件数量制造重构任务 |

## 执行方法

使用隔离目录与现实任务；评估复杂改动时按当前授权使用无聊天历史的独立 agent。只提供用户请求、技能入口和最少原始材料，不把本页验收答案或既有结论交给执行者。评估者可按入口路由参考。仅允许临时夹具内修改，复用已有依赖；不得更改主项目或真实业务数据。

比较输入和实际产物，检查越界、参考读取范围及结果真实性。需要运行的 React 场景做相应类型与交互验证；真实 Chrome 场景使用用户授权的测试页面。不能用静态推导冒充运行通过。发现问题后修正规则，用新上下文复测相关场景，最多两轮，仍失败则保留缺口。

分别记录结构检查、隔离任务判断/产物、真实浏览器、自然触发及跨模型覆盖。明确哪些未执行；显式提供技能入口的评估不能证明自动发现有效。清理无用夹具，保留精简结果与必要回滚资料。

## 软件工程扩展评测

可复用输入与预先声明的断言见 [cases.json](cases.json)，夹具位于 fixtures。对照执行使用独立上下文，每个版本独立目录；真实项目服务始终不参与。开发启动桩只写入调用记录，不监听端口。

完成独立执行后，运行 `python3 check_artifacts.py <run-directory>` 核验源码差异、启动记录、订单归属和只读复现产物；该脚本只运行已知的隔离 Node 检查，不替代执行者、报告审查或自然触发评测。
