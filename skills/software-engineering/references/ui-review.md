# 浏览器 UI Review

审查用户实际看到和操作的页面。先确定目标 URL、任务范围、验收条件或设计参考；按目标页面的真实内容、关键视口与相关状态选择场景，不默认扩成全站审计。只读审查允许授权范围内的页面导航和非破坏性交互；提交真实业务、发送消息、付款、删除等外部影响操作需要已有明确授权。

## 连接与基线

发现并读取可用的 `chrome-browser-validation` 技能，通过官方 Chrome 插件连接用户现有会话，遵循其运行时发现、连接诊断与标签页规则；不要在本文件维护客户端路径、API 或浏览器 ID。当前用户明确指定其他方式时遵循其要求。

若连接技能缺失，发现官方 Chrome 工具及当前操作文档，确认已有 Chrome 扩展连接并完成轻量通信验证后再使用。无法确认运行时或连接时，报告具体已知障碍，继续可完成的源码检查；不自行启动无头或独立浏览器替代，不声称用户未开启插件，不用旧截图证明本次结果。

确认实际访问的是目标版本与页面，记录 URL、视口和必要的起始状态。复用相关标签页，保护其他标签页、登录和用户输入；验证后尽可能恢复本次修改的视口与临时页面状态，不清除用户原有数据。

## 按用户流程审查

| 场景 | 检查方式 |
| --- | --- |
| 布局与响应式 | 按实际断点检查关键宽度和变化附近；观察区块间距、横向溢出、裁切、遮挡、固定层、弹层和滚动容器，不能只看首屏；混排组件库时按[间距 bad case](styling.md#区块间距声明不等于生效)核对实际边界与计算样式，不能只检查 utility 声明 |
| 内容适应 | 用可用的长文本、空列表、较多条目检查换行与可读性；仅在授权测试环境构造数据，不改真实业务记录凑场景 |
| 完整交互 | 操作展开、筛选、分页、选择、取消、关闭与重开；核对状态保持/重置、返回与刷新后的契约 |
| 加载与失败 | 检查已有 loading、empty、error、disabled、retry 路径；缺少安全可达条件时说明未测，不伪造网络或状态证据 |
| 键盘与焦点 | Tab/Shift+Tab、Enter/Space 及控件适用的 Escape/方向键；检查焦点可见、顺序、弹窗进入/返回及必要的焦点约束 |
| 可访问性 | 结合语义 DOM/可访问树检查名称、标签和错误关联，不以颜色独自传递状态；自动检测不能代替键盘操作 |
| 主题与动效 | 在项目支持且本次受影响时检查主题、缩放、reduced-motion 等；可测量时验证对比度，不用肉眼声称精确达标 |
| Canvas/地图/WebGL | 查看实际画面与交互结果，DOM 存在或脚本成功不能证明渲染正常 |

每组操作后重新读取页面状态再定位下一步。截图用于证明所述状态，点击成功、接口成功或初始截图不足以证明流程通过。

## 从现象定位原因

先复现，再用当前运行时支持的 DOM、计算样式、布局尺寸、控制台和网络信息定位。区分是布局约束、层叠顺序、事件、数据还是异步时序问题。没有相应诊断能力时报告未检查项，不猜接口、不另启浏览器绕过。

样式值须结合覆盖后的实际值；控制台错误须与目标操作关联，网络失败须区分预期取消与实际错误。未读取源码时可报告确认的 UI 缺陷，但将根因标为未知。不要把页面偶发现象直接归因为某个 Hook 或库。

## 输出证据

每个确认问题包含页面/视口、最短复现步骤、依据与预期、实际表现、影响及验证状态，必要时附当前截图和诊断。源码位置仅在已定位时提供。区分功能或可访问性缺陷、违反已有设计约定、主观审美建议；没有设计参考不凭偏好要求重设计。

结合源码审查时合并同根问题。列明已验证、失败和未验证路径；无法连接 Chrome 则明确“UI 未验证”，不能用类型检查、静态审查或旧截图替代。保留必要证据，清理本次自有的无用临时资源。
