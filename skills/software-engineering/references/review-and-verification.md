# 审查与验证

源码 Review 默认只读，先确定范围、基线和可达触发条件。根据本次涉及的前端、后端或 Agent 参考追踪契约；缺少基线时审查当前事实，不把既有问题归因于本次变更。

发现应有位置、触发输入、违反的契约、后果及证据。未知框架行为先核实，不用个人风格或文件长度凑问题。可用专项审查技能时按需复用，不因此扩大权限或自动委派。

| 变化 | 有区分力的验证 |
| --- | --- |
| 纯文案、间距 | 相关构建/项目门禁与必要视觉核对，不新增复述实现的测试 |
| 业务规则/缺陷 | 正常输入与暴露缺陷的边界；先验证旧行为可触发，再验证修复 |
| 接口/存储 | 消费者、权限、错误契约；涉及并发再验证事务与重试 |
| Agent 编排 | 工具输入输出、恢复、外部副作用、隔离；模型质量单独验收 |
| UI 状态/布局 | 实际页面交互、相关视口、长内容和焦点，不以类型检查代替 |

先检查验证脚本是否有外部副作用、是否会隐式启动项目服务；遵循主入口的服务控制规则。项目强制门禁仍须执行，阻塞则明确报告。已有检查通过后不为形式反复重跑；新改动、失败或未解决风险才扩大验证。

交付区分：实际修改与建议、已确认缺陷与疑点、静态推断与运行结果、合成测试与真实集成。无确认缺陷时如实说明覆盖范围，不保证没有 bug；未执行写 not_run 或未验证，不能写通过。
