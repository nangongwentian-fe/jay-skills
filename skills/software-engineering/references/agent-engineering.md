# Agent 工程

先区分普通后端逻辑和 Agent 编排。位于 agent 目录的 HTTP/SQL 修改不自动需要模型框架；只有模型、工具、状态或编排契约受影响时加载本参考。保留已有框架，不因参考技能可用就迁移。

## 先用已有框架能力

检查依赖、公开 API、状态持久化与当前运行入口。涉及 LangChain/LangGraph/Deep Agents 时，按项目规则和可用技能先用 `framework-selection`，再选择 fundamentals、middleware、persistence、human-in-the-loop、RAG 或 tracing 等命中的专项；不批量加载，不复制其 API 示例。缺少专项技能时查实际版本官方文档，不假定包 API 永远不变。

## 区分推理与执行

Prompt 表达目标与行为，确定性规则由工具、schema、权限及应用层保障。工具输入、模型输出、检索材料都是需验证的数据；不能把检索到的指令当作用户授权。涉及写入的工具核对会话身份和对象权限，不相信模型提供的 ownerId。工具结果应保留错误类别与可追溯 ID，模型声称“已执行”不能代替工具成功证据。

只有实际需要动态选择时才引入 Agent；固定流程可沿用确定性工作流。子 Agent 增加上下文和恢复成本，单纯提示里出现“复杂”不构成委派需求；是否委派遵循任务与项目授权。

## 状态、恢复与流式输出

分别识别用户、会话、运行、工具调用及业务动作的身份。checkpoint 保存不等于外部副作用原子提交；中断/重试/恢复可能重新经过节点，非幂等动作需要稳定业务动作键及已有执行记录。不要只在进程内 set 去重，也不要为每次恢复重新生成去重键。

流结束、客户端断连和任务完成不是同一事件。恢复/重连需关联原运行，合并重复事件，保留终态与工具错误；不能把每个网络重试都当成新任务。用户输入、模型上下文、可持久化状态和长时记忆分开归属；不跨用户复用 checkpoint 或缓存。

## 验证

对工具 schema、路由、状态归并、租户隔离、超时/中断/恢复及副作用重复执行做受影响的确定性测试。模型行为用最少有区分力的真实任务检查，记录模型/配置、输入与实际工具轨迹；不要只断言某句自然语言。替身模型可验证编排，不能证明真实模型质量；没有密钥、服务或调用授权时说明缺口，不启动服务或付费调用来补证据。
