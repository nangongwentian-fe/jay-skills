# 样式组织与复用

沿用项目现有方案。已有 Tailwind 时优先用完整、可静态检测的 utility class 及其组合表达常规样式；只有它不适合清楚、稳定表达的局部规则才放入组件 CSS/SCSS Module。不能因为 className 较长或已有 Module 文件就搬走常规样式。无 Tailwind 的项目不因此迁移。

| 需求 | 选择 |
| --- | --- |
| 布局、间距、排版、主题、常规交互状态 | 现有 utility、token、variant 或项目样式机制 |
| 复杂选择器、关键帧、局部第三方覆盖 | 项目已有组件局部样式方案，限制作用域 |
| reset、字体、主题令牌、全局基础规则 | 全局入口 |
| 不能静态枚举的运行时值 | 局部 CSS 自定义属性，必要时 inline style |

写样式前检查当前范围的重复与已有组合，优先复用基础 class、设计令牌、variant 和条件 class 工具。同一语义的样式可组合共享基础与差异变体；形似但独立变化的规则不强制抽象。样式组合足够时不新增样式库或 SCSS 抽象层。共享结构、行为与契约时才考虑组件，循环渲染不等于源代码重复。

## 区块间距：声明不等于生效

新增或修改表单、步骤条、工具栏、提示区等布局时，明确谁负责区块之间的间距；组件内部 padding 不等于组件之间的留白。尤其是 utility 与组件库混排，不能看到 `space-y-*`、`mb-*` 或 `gap-*` 就认定页面已有间距。

### Bad case：步骤条贴住表单

已验证案例（2026-11-16，AeroTwin 任务向导）：父容器使用 Tailwind `space-y-7`，直接子元素为 Ant Design `Steps` 和表单 section。步骤条的组件样式覆盖了 utility 施加的 margin，计算后的下边距为 0，步骤条底部与表单顶部重合。源码看起来有间距，实际截图却没有。用普通外层容器承接原有区块间距后，实测恢复为 28px，切换下一步后仍有效。这是特定组合的实测结果，不代表所有版本的 Steps 都有此问题，也不把 28px 规定为全局标准。

```tsx
// 脆弱：区块间距直接落在组件库根节点上，可能被它的 reset 覆盖。
<main className="space-y-7">
  <Steps items={items} />
  <section>...</section>
</main>

// 局部修复：由布局拥有的普通容器承接间距。
<main className="space-y-7">
  <div><Steps items={items} /></div>
  <section>...</section>
</main>
```

| 情况 | 选择与核对 |
| --- | --- |
| 已有普通流布局，仅组件根节点 margin 被覆盖 | 可用薄包装容器隔离组件 reset，保留语义、宽度及既有对齐；不要给所有组件机械加一层 |
| 新建或本就适合 flex/grid 的区块排列 | 优先考虑父容器 `gap`；确认父元素实际启用了 flex/grid，检查子项宽度、收缩与换行；不要只添加无效的 `gap` |
| 使用 `space-y` 或子元素 margin | 核查实际 DOM 兄弟关系、条件渲染、Fragment、多根子组件及 CSS 层叠；查实际安装版本生成的规则，不假定 utility 总能覆盖组件库 |
| 需要局部样式覆盖 | 先定位获胜规则、层叠层、优先级和加载顺序，再选最小作用域；不要默认堆叠 `!important`、全局覆盖 `.ant-*` 或混用 gap/margin 造成双倍间距 |

验收以渲染结果为准：确认页面加载了本次版本；检查截图，并在可用时测量相邻区块的 `next.top - previous.bottom` 与计算样式。值应符合项目间距尺度，不能只验证 class 存在或 margin 声明存在。按受影响范围检查步骤切换、条件提示或窄屏排列，不为小改动做全站审计。热更新未反映修改时先核实版本，必要时安全刷新并恢复目标状态，保护用户未保存输入；不要把旧画面当成修复结果。

服务或浏览器不可用时，继续源码与一次性检查，明确标注“间距视觉未验证”及具体缺口；不擅自启动服务、不用静态通过代替页面验收。浏览器操作仍由 `chrome-browser-validation` 指引负责。

## 重构与迁移

先标明每条规则属于组件、主题、布局、第三方还是全局。职责混杂、消费者分散或 DOM 耦合才是拆分依据，文件长度只是调查线索。

视觉不变重构先记录 class 绑定、媒体查询、关键帧和全局逃逸，再按所有权移动并更新 import。保留 specificity、加载顺序和断点行为；删除本次移动产生的孤儿规则。不要把不同组件的局部规则集中成巨型共享样式文件。项目采用 Next.js 等 CSS 分块框架且修改入口或顺序时，检查生产产物，不能只看开发环境。

新增依赖、构建机制或扩大迁移超出已有授权时，提出具体范围、收益、风险与验证方式后确认；已有授权不重复询问，不因偏好主动更换技术栈。

## 验证

按影响选择真实页面的断点、交互状态、主题和动效检查，保留项目门禁。关注全局泄漏、被裁切内容、焦点可见性和覆盖顺序。纯样式修改不要求无关逻辑测试；涉及构建入口或 CSS 顺序时验证生产构建。不为本次任务擅自引入 lint、截图或样式依赖。
