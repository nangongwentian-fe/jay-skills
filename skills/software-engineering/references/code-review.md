# 前端源码 Review

默认只读。确认目标文件、模块或 diff、用户验收条件和可用基线；缺少基线时审查当前实现，不将既有问题归因于本次改动。不安装项目依赖、不更新快照、不修源码或配置；可运行安全的现有检查，在允许的临时目录做最小复现。

可用时读取 `code-review` 技能，复用其通用审查与定级方法。以下是前端专项线索，按风险选取，不逐条机械全量扫描。需要架构、状态或样式细则时按技能入口读取对应参考。

| 领域 | 追踪的契约与候选问题 |
| --- | --- |
| 模块与组件 | 共享层反向依赖页面、运行时循环、私有实现被跨模块消费、职责混杂导致修改扩散；不以目录名称或行数判错 |
| 状态与身份 | 重复来源、派生值同步、失配的受控/非受控模式、不稳定 key、嵌套组件定义造成草稿重置 |
| Effect 与异步 | 缺少清理、过期响应覆盖、闭包依赖错误、重复提交；追踪触发、取消、失败和重试路径 |
| 数据与路由 | 缓存键遗漏参数、失效范围错误、URL 与筛选不一致、前进后退恢复、客户端导入服务端模块 |
| 样式 | 动态拼接不可扫描的 utility、全局泄漏、冲突规则、错误的主题/variant 复用；结合实际构建配置与消费方判断 |
| 交互与语义 | 可访问名称、原生控件、表单错误关联、键盘路径、焦点管理；自定义可点击容器不能仅有鼠标行为 |
| 性能 | 可达的串行请求、明显重复工作、大列表和资源加载；用数据支持瓶颈与改善，不默认添加 memoization |
| 客户端边界 | 不可信 HTML/URL 进入危险渲染路径、敏感服务端配置流入客户端；隐藏按钮不能替代服务端鉴权 |

## 验证候选问题

从用户操作或外部输入追踪到状态、请求和渲染结果，读取必要调用方，排除框架、查询库或组件库已经处理的情况。不要把未知 API 行为当成 bug；先核对项目实际版本与公开契约。

为问题给出可达触发条件、违反的契约和实际影响。能够安全复现时运行已有测试或最小验证；无法运行时明确静态证据与待验证部分。源码能确认的行为缺陷不因缺少浏览器而丢弃；仅凭代码猜测的视觉问题应保留为疑点。

## 报告

按后果分级：P0 紧急严重、P1 高影响、P2 普通需修复、P3 低影响。每条包含具体文件与最小行范围、触发条件、证据、影响、验证状态和修复方向；缺少源码时不编造位置。

同根代码与 UI 发现合并。风格偏好与无证据的抽象建议单列，不凑问题数量。说明基线、覆盖的正常/异常路径和未验证范围。无确认缺陷时写“本次审查未发现可确认的问题”，不保证无 bug。修复请求另按已有授权进入开发路径。
