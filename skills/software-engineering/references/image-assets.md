# 前端图片资产交付

接入生成图、导出图或现有位图时读取。生图完成不等于前端资产交付；CSS 缩小显示不会减少下载字节。仅调整普通布局时不扩大为全站图片审计。

## Bad case：生成背景后直接用于页面

仿真任务页曾把 2172 × 724 的生成 PNG 转成同尺寸 JPEG（198,894 字节），却没有按页面尺寸优化，也没有评估现代格式。后来从原始无损 PNG 生成 1800 × 600 的 WebP（39,042 字节），更新页面引用和图片固有尺寸，实际加载字节减少约 80.4%。页面最大内容宽度为 1800px，保留了 3:1 构图。

教训是必须完成尺寸、编码、接入和验证；1800px、WebP quality 80 及这次压缩率只是该案例的选择，不是全项目硬指标，也不代表所有 DPR 场景最佳。

## 实施与验收

1. **先确认用途和显示约束。** 查看消费者的最大显示宽度、响应式布局、目标 DPR、裁切方式及清晰度要求，检查源文件真实尺寸、格式和字节数。按需要缩放，保持比例；`object-fit: cover` 的可见区域也需检查。确有收益时提供多尺寸与 `srcset`／`sizes`，不机械生成多份文件，不为小图无意义放大。
2. **选择适合内容的编码。** 照片、宇宙背景等位图优先评估 WebP／AVIF 与目标浏览器支持，按视觉质量和体积选择参数；优先从原始无损源处理，避免连续有损转码。SVG 图标保留矢量，透明图保留 alpha，动图保留动画；用户指定格式或兼容性要求优先，不强制全部转 WebP。
3. **实际产出并接入。** 优先复用现有图片工具和项目流水线，不仅改扩展名或 CSS。更新真实消费者、必要的固有尺寸／比例和资产来源记录。确认没有引用后清理本次替代的重复发布文件，保留用户原稿、必要回滚资料，不顺带删除其他图片。
4. **验证交付。** 检查输出真实编码、尺寸、字节数与前后变化，并查看图像的清晰度、构图、透明边缘等适用项目。运行相应一次性构建或检查；页面可用时核实实际加载的是新资源、固有尺寸正确且无破图，再验收不同布局下的裁切和可读性。构建成功不能代替页面视觉验收；服务未启动时继续离线检查，明确浏览器未验证，并遵循入口的服务控制规则。

交付简述旧／新格式、尺寸、体积，以及实际验证范围。不要仅报告“已压缩”或把离线文件检查说成真实浏览器加载成功。
