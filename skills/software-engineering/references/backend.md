# 后端工程

先从路由/调用者追踪到用例、存储和外部服务，确认当前认证方式、数据归属、契约与运行环境。以下按本次风险选取，不为普通字段修改引入全套架构。

## 接口与权限

在信任边界验证输入，复用现有 schema 与错误映射。认证身份来自受信会话或服务上下文，不能由请求体的 userId/tenantId 自证；读写对象时检查对象归属，隐藏前端按钮不能替代服务端授权。校验失败、未登录、无权访问、不存在和执行失败按项目契约区分，不把异常伪装为成功或空数据。

改变响应字段、分页、排序或错误形状时核对实际消费者。游标和排序必须共同定义稳定顺序；不要仅因数据库当前顺序看似正确就依赖它。查询使用项目参数化接口，批量读取按实际负载和访问计划判断，不无依据宣称性能提升。

## 写入与并发

先确定业务不变量和事务边界。需要原子的多步写入由存储层事务/约束保障，应用层“先查后写”不提供并发唯一性。乐观版本检查覆盖写入条件；失败不得留下半份状态。幂等键应绑定调用者与请求语义，重试复用已完成结果，不重复扣费、发消息或创建任务。

网络超时可能表示结果未知，不能直接断言操作失败后安全重做。只对可重试错误进行有界重试；按已有机制处理超时、取消和部分成功，不手写第二套通用重试框架。日志记录相关请求/任务 ID 和错误类别，避免凭据与完整敏感载荷。

## 数据与验证

Schema 改动核对历史记录、默认值、约束、读写版本与回滚条件；不要在没有授权的真实库执行迁移、重置或 seed。复用项目迁移机制，区分代码检查与实际迁移验收。

按影响验证成功、非法输入、跨用户访问、竞争或重复请求、外部失败。可用纯函数/内存适配器做隔离测试，但明确它不证明数据库事务、真实权限链路或线上集成正确。需要数据库/项目服务时由用户启动。
