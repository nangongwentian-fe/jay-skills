# 技能行为评测

验证技能是否使 Agent 完成用户任务。与 `skill-creator` 分工：后者负责创建和修改，本技能负责执行和判定；静态校验、阅读审查和“我会怎么做”的回答都不能代替行为证据。

## 选择评测范围

- 新建技能或改变触发条件、步骤、权限边界、失败恢复、输出契约时，交付前执行受影响行为及关键回归用例。纯错字、排版或不改变含义的链接修复只需静态检查。
- 优先复用目标技能的现有用例和历史失败。小改动采用少量有区分力的场景；新流程通常从 2–3 个真实任务起步，再补关键异常。不要把固定数量或全量 benchmark 作为所有修改的门槛。
- 编辑已有技能前保留旧版及其必要资源作为基线。事后没有可信旧版时明确基线缺失，不能编造旧版或据此声称性能提升。新技能可对比不加载该技能的基线。
- 分别标记静态校验、决策模拟、实际任务执行、真实服务集成和自动触发测试。只声称实际覆盖的层级；使用模拟浏览器不能证明 Chrome 集成可用。

## 执行流程

具体用例、执行提示和结果结构见 [评测指南](references/evaluation-guide.md)。执行评测时读取；维护本技能时另读 [自测场景](evals/scenarios.md)。

1. 明确改动和成功标准，准备输入、前置状态及可验证断言。关键断言在执行前确定并与执行者隔离；不要运行后放宽标准来制造通过。场景需覆盖正确完成、适用边界及受影响的失败恢复。
2. 为每个用例和版本使用隔离输出目录。输入和技能视为只读；固定同一输入、环境和模型配置，记录技能内容指纹及运行配置。不得让一轮遗留文件或登录状态替下一轮完成工作。
3. 使用 Codex 当前提供的子 Agent 工具独立执行，本技能明确要求为行为评测委派执行者。优先 `fork_turns="none"`，只传任务、目标技能路径、必要输入、环境约束和输出目录；不传作者推理、预期答案、断言或另一版本的结果。按可用槽位分批，不硬编码模型，也不假定子 Agent 可并行修改共享资源。没有独立执行能力时报告限制；同一上下文推演只能标为模拟或审查，不能宣称独立 eval 已通过。
4. 新版与基线分别执行。角色登录、浏览器会话和其他共享外部状态须串行恢复或隔离；使用真实服务仍遵守目标技能及用户已有授权。评测本身不授权生产写入、付款、发信、改密或扩大凭据访问。可用假凭据与工具模拟检验决策，但必须标注模拟范围。
5. 收集实际产物、可核查执行记录、错误和工具结果，再评分。可确定性验证的内容使用脚本检查实际产物；过程要求检查调用记录，不采信执行者自报“通过”。主观质量使用明确标准与必要的人审，比较时尽可能隐藏版本身份。关键结论缺证据不能通过。
6. 按 `pass`、`fail`、`blocked`、`not_run` 报告每条断言；发现真实缺陷后修正技能并重跑受影响用例及必要回归。未执行或环境阻塞保持未验证，不算通过，也不伪装成技能失败。必要行为未验证时整体为不完整，不能宣布技能已通过验收。
7. 汇总结果与证据，区分正确性、回归和相对改善。单次执行只能证明该次结果；仅在确有重复测量时报告方差，token 或耗时不可得则写未知，不估造指标。无提升不等于失败：关键行为满足且无回归仍可交付，但不得声称优于基线。

## 交付与留存

保留可复用的用例、最小输入夹具、断言，以及支撑最终结论的脱敏报告和必要产物。清理本次无用临时环境与重复输出，不能删掉唯一证据后保留“已通过”的结论。报告写明版本、运行环境、执行层级、通过/失败/未验证数量、证据位置和限制。

该流程是 Agent 执行约定，不是后台监听器或系统强制 hook。自动触发是否有效必须另行测试，不能用 `allow_implicit_invocation: true` 或显式调用成功证明。

评测 `skill-eval` 自身时，以真实评测任务检验其行为，完成一层执行与评分即可；执行者不要递归创建“评测评测器”的无限链。评测已有产物的用例可直接独立评分，无需重新运行产物生成任务。

## 来源与适配

采用 Anthropic 官方 [skill-creator](https://github.com/anthropics/skills/tree/main/skills/skill-creator) 的任务用例、基线比较、证据评分和迭代方法，针对 Codex 的子 Agent 与工具能力编写流程。未捆绑或调用 `claude -p`，不把 Claude 的触发结果当成 Codex 的结果；数据格式与其工具没有宣称完全兼容。
