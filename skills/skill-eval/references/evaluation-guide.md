# 评测执行指南

## 用例设计

用例描述真实任务及原始状态，断言描述结果与可观察行为。不要把“必须先调用 X 再调用 Y”写进用户任务来提示答案，除非调用顺序本身就是用户需求。避免仅检查关键字、文件存在或 Agent 承诺。

建议在目标技能的 `evals/` 保存用例和最小夹具。结果放在明确的评测输出目录，不混入产品代码。已有格式可复用；新建时可采用：

```json
{
  "skill_name": "example",
  "cases": [{
    "id": "recover-after-login",
    "prompt": "验证管理端刷新和页面切换的加载效果。",
    "inputs": ["fixtures/project"],
    "preconditions": "浏览器为学生会话，项目配置包含可用测试管理员账号。",
    "level": "simulation",
    "assertions": [
      {"id": "resume", "critical": true, "expectation": "切换账号后实际执行刷新和页面切换验证。", "evidence": "工具调用记录与页面状态"}
    ]
  }]
}
```

这里的路径由用例文件位置解析，执行前展开为绝对路径。不要把真实秘密保存进夹具；模拟凭据须明显为测试数据且不能被提交到真实站点。

## 独立执行者

在当前工具目录确认委派工具。使用新上下文，给每一版本独立输出目录，提示例如：

```text
执行任务：<原始用户请求>
使用技能：<目标 SKILL.md 的绝对路径；无技能基线则省略>
输入：<绝对路径>
环境与允许操作：<必要约束>
输出目录：<该版本专属绝对路径>
完成实际工作，保留产物，并在最终回复记录做了什么、证据路径和任何阻碍。
不得修改输入或技能，不读取其他版本、评分文件或作者聊天。
```

保持父上下文里的答案、测试断言、预期失败和旧版结果不进入执行者上下文。子 Agent 可能仍继承系统规则或技能目录；记录这一点。无技能基线若实际读取目标技能，则该基线被污染，不能用于有效对照。无法隔离自动技能加载时优先用旧版基线，或明确放弃相对收益结论。

父 Agent 需检查工具返回与产物本身。必要时让执行者回报具体工具调用标识；只写一份自述日志不足以证明某项外部动作发生。工具接口不暴露完整轨迹时记录缺口，不能生成伪造 transcript。

## 评分与门槛

每条断言需写 verdict、具体证据和理由：

- `pass`：实际结果与可信证据共同支持。
- `fail`：已执行但不满足要求；例如只生成空文件、输出错误，或应保留证据却遗漏。自报完成但缺乏必需产物不能通过。
- `blocked`：环境、权限或外部依赖阻止执行或核实；描述阻碍，不推断技能行为正确或错误。
- `not_run`：尚未执行。

计数始终包含四种状态。若报告执行断言通过率，用 `pass / (pass + fail)` 并同时报告覆盖 `已判定 / 总数`；分母为零写未知。关键断言有 fail 则整体 `fail`；有关键 blocked/not_run 则整体 `incomplete`；全部必需用例和关键断言有证据通过且无不可接受回归才为 `pass`。非关键项的例外须在执行前约定，不能事后将失败降级。

结果可用 JSON 或 Markdown；至少记录这些事实：

```json
{
  "skill": "example",
  "candidate_fingerprint": "sha256:<实际计算值>",
  "baseline": "旧版指纹或 none；缺失则说明",
  "environment": "实际工具和执行环境",
  "level": "actual_task",
  "overall": "incomplete",
  "counts": {"pass": 1, "fail": 0, "blocked": 1, "not_run": 0},
  "results": [
    {"case": "normal", "assertion": "content", "verdict": "pass", "evidence": ["outputs/result.csv"], "reason": "实际内容校验通过"},
    {"case": "live-login", "assertion": "resume", "verdict": "blocked", "evidence": [], "reason": "当前会话无可用 Chrome 扩展连接"}
  ],
  "metrics": {"tokens": null, "duration_seconds": null},
  "limitations": ["未验证真实登录"]
}
```

指纹需涵盖此次执行用到的技能正文、脚本和参考文件；用路径与文件哈希清单也可，不只记录可能重复的版本名。模型、时间指标只记录工具实际暴露的信息。

## 基线与迭代

优先比较同一任务的完成情况及副作用。新旧版相同环境下逐项评分；对主观产物可用匿名 A/B 评分，评分者不读取实现。若改动影响工具选择或交互过程，必须同时检查执行证据，不能只比较最后回复。

候选失败时定位原因，修正后保存新指纹并重跑相关用例，保留有解释价值的失败证据。不要调整断言来迁就输出。重复运行用于确认不稳定行为，不是反复抽样直到某次通过；报告所有相关尝试。

## 触发评测

显式要求使用技能只验证执行能力。自动触发评测必须在真实 Codex 新上下文中，仅提供自然任务以及正常可发现的技能目录，观察实际是否读取目标技能；正例检查漏触发，接近但不适用的负例检查误触发。不得先在提示中告知应该调用哪个技能。

若工具不能提供这样的会话、目录或读取证据，标记自动触发未验证。不要为了测试自动触发创建用户可见的新聊天，除非用户明确要求创建聊天。不要直接使用 Anthropic 的 `claude -p` 触发脚本替代 Codex 评测。
