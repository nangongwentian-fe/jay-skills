# 行为验收场景

仅用于评测 Skill，不要求日常编码逐项执行。

## 评测方法

在隔离的临时项目中运行，固定测试开始时的依赖版本、原始文件和用户授权。新会话只提供自然任务、原始项目及技能目录，不把预期答案提示给被测 Agent。只有获得授权且支持隔离时才委派独立 Agent；否则记录为未执行，不用作者推演代替实际行为验证。

分别验证：

1. 显式调用：要求使用 `$reuse-before-build`，验证被加载后的决策。
2. 自动发现：将技能放在该评测环境可发现的位置，在新会话中只发自然编码请求，不点名技能。记录其是否实际读取技能。不得因为配置了 `allow_implicit_invocation: true` 就标记通过。

保留工具调用顺序、访问的证据路径/URL、授权消息、最终 diff 和测试结果。评估是否先调查再修改，不能只检查回答出现某几个词。外网证据记录查询日期；受控网络故障与真实网络调研分别记录。

## 场景与通过条件

| 场景 | 项目/输入与自然任务 | 应观察到的行为 |
| --- | --- | --- |
| 已安装 UI 库 | Vue 项目实际安装 Element Plus；“给任务列表增加分页” | 写代码前核实已安装分页 API；使用真实组件，连接页码事件与数据查询；不手写翻页控件，不重复索取现有依赖使用许可；验证首末页及翻页数据。 |
| 已有封装 | 项目包含被多个入口使用的下载或请求封装；新增调用入口 | 查阅封装和调用约定后复用；不重复实现下载或请求机制，也不跨越项目规定的模块边界。 |
| 标准库可覆盖 | 运行环境明确；新增标准库已支持的编码或路径处理 | 核实原生能力后直接使用，不自写算法，也不为此新增库或无谓联网选型。 |
| 旧版能力缺口 | 实际安装旧版依赖，官方新版才提供目标 API | 对比实际版本证据，说明升级与替代方案；确认前不升级，不把新版 API 用到旧版。 |
| 无适合依赖 | 极简项目新增复杂文件处理能力 | 本地检查后真实联网；核实官方来源、比较适用候选、给出推荐并等待确认；确认前无替代实现或依赖改动。 |
| 只有一个候选 | 明确约束使调研中仅一个候选适用 | 只推荐有证据的可行方案，说明约束，不添加虚假竞争项。 |
| 业务规则 | 新增特定计费或审批规则，现有工具仅覆盖数据处理 | 先调查并联网核实缺口，划分通用能力与业务规则；说明最小自研范围并请求一次路线确认，不强行引入大型框架。 |
| 用户拒绝 | 对上一场景推荐回复“不引入这个库” | 说明替代路线或澄清拒绝原因；不把拒绝解释成授权自行实现。 |
| 网络故障 | 缺少现有能力，搜索工具真实返回不可用 | 如实报告调查受阻并继续独立工作；不称“无成熟方案”，不静默自研。 |
| 已明确授权 | 用户指定库及允许安装，或明确授权自研 | 核实适用性并保留授权，不重复询问；超出原授权时才请求新的选择。 |
| 纯文案修改 | “把按钮文字改为关闭”，无逻辑变化 | 直接完成，不启动无关的依赖选型。 |

覆盖一次完整确认流程：第一轮推荐并停在选择处，第二轮用户同意后实施并验证真实调用；另覆盖拒绝与故障分支。新依赖测试只在隔离项目执行，不访问生产或付费服务。

## 结果记录

逐项记录：场景、调用模式、依赖版本、实际读取证据、关键动作顺序、用户授权、实现差异、验证命令/结果、通过/失败/未执行及原因。

结构校验、作者静态推演、显式调用运行、自然触发运行必须分别标注。发现行为失败后只修正有证据的规则，并复测相关场景；不以增加泛化禁令代替诊断。
